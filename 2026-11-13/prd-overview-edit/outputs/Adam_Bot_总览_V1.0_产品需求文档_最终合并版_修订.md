# Adam Bot「总览」V1.0 产品需求文档

> 文档版本：V1.0（最终合并版）  
> 文档状态：本轮需求评审已确认  
> 所属产品：Adam Bot / AI Agent 工作台  
> 关联文档：《AI Agent项目 V1.0需求文档》  
> 范围说明：本文定义「总览」的展示、统计、筛选和联动规则，并明确与 AI Agent「收件箱 → 已解决」保持一致的会话判定标准。除本次明确的补充外，不修改原有会话生命周期、AI 接待流程及其他模块功能。

---

## 1. 需求背景与目标

### 1.1 需求背景

Adam Bot 已支持通过 AI Agent 接待客户咨询，并通过「收件箱」查看会话。为帮助运营及客服管理人员了解 AI 的服务表现，新增一级菜单「总览」，集中展示会话规模、有效性、AI 独立解决情况及转人工情况，并允许从 AI 解决率趋势直接进入对应的已解决聊天记录。

### 1.2 产品目标

1. 在一个看板中查看**会话数、AI 解决率、转人工率**三个核心指标。
2. 在会话数卡片内细分**有效会话数、无效会话数**，避免无效咨询干扰 AI 解决率。
3. 允许按时间、AI Agent、渠道实例组合筛选，并查看与上一周期相比的变化。
4. 通过一张可切换指标的趋势图观察指标变化。
5. 选择「AI 解决率」时，可以跳转「收件箱 → 已解决」，并继承当前筛选条件查看对应会话。

### 1.3 本次功能范围

**包含：**「总览」一级菜单及角色管理权限、全局筛选、三张指标卡片（含会话有效性细分及较上期对比）、一张趋势图及下拉指标切换、「查看已解决会话」跳转、统计口径、状态/异常处理、收件箱已解决判定一致性。

**不包含：**新增「待判定」指标、独立有效/无效列表、未解决指标卡片、多张图表、排行榜、导出、定时或实时刷新、TG 转人工链接点击追踪、发送链接后 N 分钟判断、其他监控系统数据排查、按钮级权限配置、独立的分析明细页。除指定按钮外，指标卡片和趋势图不增加额外下钻。

## 3. 统计范围与基本定义

### 3.1 统计对象

| 概念 | 定义 |
|---|---|
| Conversation（会话） | 客户在某一渠道下与 AI Agent 形成的一次完整咨询；多轮消息计为同一个 Conversation |
| 正式会话 | 通过正式接入渠道产生的会话；不含 AI Agent「预览与测试」的模拟聊天 |
| 已结束会话 | 已按现有会话生命周期关闭的会话，原会话不可重新进入处理中 |
| 有效会话 | 已结束，且聊天内容存在真实业务咨询的正式会话 |
| 无效会话 | 已结束，但聊天内容不包含真实业务咨询的正式会话 |
| AI 已解决 | 已结束且有效，由 AI 至少解决一个实际业务问题，且**整场会话没有触发转人工** |
| 转人工 | AI 实际触发了对应渠道的转人工行为：LiveChat 执行转人工指令；TG 成功发送转人工链接 |
| 未解决 | 已结束且有效，既未触发转人工，也未达到 AI 已解决条件的会话 |
| 时间归属 | 按**会话创建时间**归入统计日期，而非消息发生、转人工、解决或关闭的时间 |

### 3.2 统计集合

1. **「总览」中的所有指标均仅统计已结束的正式会话。**尚处于「处理中」的 Conversation 不计入总览的会话数、有效/无效数、解决率和转人工率，也不计入趋势或同期对比。
2. 仅使用当前租户数据，按 Conversation 唯一 ID 去重；同一客户发送多条消息或在同一会话中咨询多个问题，仍仅计为一场。
3. AI Agent 的「预览与测试」模拟聊天不计入统计。
4. 已结束的正式会话必须按第 3.3 节划分为**有效**或**无效**，不新增「待判定」类别和卡片。
5. 已结束后客户再次发送消息，按照现有规则建立新 Conversation 时，新会话结束后可单独计数。
6. 不修改 AI Agent「收件箱」原有的**处理中、已解决、已结束**分组；「总览只统计已结束」是本模块的统计口径，不代表系统不再存在处理中会话。
7. 总览统计结果可以随会话结束或已结束会话判定更新而回算到原创建日期；用户重新进入、改变筛选或手动刷新后显示最新结果。

### 3.3 有效 / 无效判定标准

**核心原则：依据是否存在真实业务咨询，不依据 AI 最终有没有解决、客户是否继续回复或者是否提供所需资料。**

| 具体场景 | 有效性 | 说明 |
|---|---|---|
| 客户仅发送「你好」「在吗」等寒暄，无业务诉求 | 无效 | 未形成实际业务咨询 |
| 纯广告、垃圾消息、无关内容、纯辱骂，无业务诉求 | 无效 | 无实际业务咨询 |
| 客户提出真实业务问题，即使只发一条消息就离开 | 有效 | 不按消息轮数或是否回复排除 |
| 客户提出真实业务问题，但 AI 未给出正确解决方案 | 有效 | AI 未解决不能反推会话无效 |
| AI 要求客户补充账号、截图，客户未继续提供 | 有效 | 真实业务咨询已存在，信息收集未完成 |
| AI 给出处理方案后，客户未回复确认 | 有效 | 是否「已解决」另按解决结果判定，不改变有效性 |
| 同一会话包含多个实际业务问题 | 有效 | 同一个 Conversation 仍只计一场 |
| 真实业务咨询随后触发转人工 | 有效 | 结果为转人工，有效性不改变 |

- 若会话同时包含寒暄、辱骂或无关内容与**真实业务问题**，不能仅凭这些非业务片段直接判为无效；按整个会话是否包含真实业务咨询判断。
- 有效/无效为会话的**独立分类维度**；「已解决/转人工/未解决」为有效会话的最终**处理结果维度**。
- 不因「AI 未给出方案」或「客户没有继续回复」自动把真实业务咨询归为无效。
- 本期不新增人工审核入口、有效性手动标注入口或可配置的评判规则。

### 3.4 有效会话的最终处理结果（互斥）

已结束的**有效会话**只能对应以下三种结果之一，依次判断：

| 优先级 | 条件 | 最终结果 |
|---|---|---|
| 1 | 曾触发过符合第 3.5 节定义的转人工行为 | **转人工** |
| 2 | 未触发转人工，且 AI 至少解决一个真实业务问题，符合现有 LLM 已解决判断 | **已解决** |
| 3 | 未触发转人工，且 AI 未达到「已解决」条件 | **未解决** |

**强制互斥：**同一场会话不能同时算作 AI 已解决与转人工。即使 AI 先解决了一个业务问题，客户后续又提出另一个问题并触发转人工，该 Conversation 也最终归属「转人工」，不计入 AI 已解决分子。

- 沿用原 AI Agent「已解决」的要求：**AI 至少解决一个实际问题，且会话已结束**。
- 对原 PRD「无需人工介入」作明确补充：**整场会话没有触发转人工**。这不是把「至少解决一个」改成「必须解决所有问题」，而是排除转人工与已解决双重计数。
- 单纯寒暄、纯测试、纯无关消息不视为已解决。
- **未解决**仅作为有效会话的处理结果类别参与统计定义，本期不新增未解决指标卡片，也不新增收件箱分组。
- 总览的「AI 已解决」按本节判定；「收件箱 → 已解决」沿用其现有判定，会话是否触发过转人工不作为「已解决」的排除条件。

### 3.5 转人工判定（按渠道）

| 渠道 | 统计为转人工的触发条件 | 不计入的情况 |
|---|---|---|
| LiveChat | AI Agent 实际执行转人工指令 | 仅在聊天中提及人工、客户要求人工但尚未触发指令 |
| TG | AI Agent **成功发送转人工链接** | 仅提及人工但未发链接、转人工链接发送失败 |

1. 转人工是 AI **发起转人工动作**的业务判定；对于 TG，不代表客户已经点击链接或成功获得人工接待。
2. **不追踪 TG 链接点击，不等待 N 分钟，不根据链接发送后客户是否继续发消息修改转人工判定。**
3. 每场 Conversation 最多统计**一次**转人工；重复消息或重复呈现同一链接不增加计数。
4. 「转人工优先」仅影响最终会话分类，不修改原有 AI Agent 对话关闭时机或转人工接待方式。
5. 已结束的无效会话即使存在转人工触发事件，也不计入**转人工率分子**；只有有效且已结束、最终归类为转人工的会话计入。

## 4. 核心数据指标

### 4.1 统计变量和校验关系

对当前日期、Agent、渠道筛选结果中的**已结束正式会话**定义：

- **N：会话数**；
- **V：有效会话数**；
- **I：无效会话数**；
- **S：AI 已解决的有效会话数**；
- **H：转人工的有效会话数**；
- **U：未解决的有效会话数**。

必须满足：

```text
N = V + I
V = S + H + U
0 ≤ S ≤ V ≤ N
0 ≤ H ≤ V ≤ N
```

同一有效会话在 S、H、U 中**只能归属一个**，不重复计数。

### 4.2 公式与卡片

| 主卡片 | 当前值公式 | 具体说明 |
|---|---|---|
| **会话数** | `N` | 已结束正式会话总数；卡片内部展示 **有效会话 V**、**无效会话 I**，且 `N=V+I` |
| **AI 解决率** | `S ÷ V × 100%` | 分子是 AI 独立解决的已结束**有效会话**，分母是全部已结束**有效会话** |
| **转人工率** | `H ÷ V × 100%` | 分子是触发转人工的已结束**有效会话**，分母与 AI 解决率相同 |

- 当 `V=0` 时，AI 解决率和转人工率均显示 **`—`**，不能显示 `0%`。
- 当 `V>0` 且 `S=0` 或 `H=0` 时，对应比率显示 **`0.0%`**。
- AI 解决率与转人工率**不一定合计 100%**；剩余部分为有效但未解决、未转人工的会话。
- 无效会话计入会话总数 N，但不计入 S、H、U 和任何比率分母。

### 4.3 具体示例

| 情况 | N | V | I | S | H | U |
|---|---:|---:|---:|---:|---:|---:|
| 仅「你好」，无业务诉求，已结束 | 1 | 0 | 1 | 0 | 0 | 0 |
| 问充值，AI 解决，未转人工，已结束 | 1 | 1 | 0 | 1 | 0 | 0 |
| 问充值，AI 未解决，客户离开，已结束 | 1 | 1 | 0 | 0 | 0 | 1 |
| 问业务，AI 索要账号，客户未提供，已结束 | 1 | 1 | 0 | 0 | 0 | 1 |
| AI 先解决充值，后续优惠问题触发转人工，已结束 | 1 | 1 | 0 | 0 | 1 | 0 |
| TG 真实业务咨询，链接成功发送，已结束 | 1 | 1 | 0 | 0 | 1 | 0 |
| TG 真实业务咨询，链接发送失败，AI 未解决，已结束 | 1 | 1 | 0 | 0 | 0 | 1 |
| 会话仍在处理中 | 0 | 0 | 0 | 0 | 0 | 0 |
| 「预览与测试」模拟聊天 | 0 | 0 | 0 | 0 | 0 | 0 |

表中每行表示**一场对应情形的会话对总览统计的贡献**。示例不改变原会话的状态流转。

### 4.4 数值格式

| 项目 | 展示规则 |
|---|---|
| 会话数、有效会话数、无效会话数 | 非负整数、千分位分隔；不加「场」等量词，例如 `1,286` |
| AI 解决率、转人工率 | 百分比保留 **1 位小数**，例如 `72.5%` |
| 较上期会话数变化 | 相对变化百分比 `%`，保留 1 位小数 |
| 较上期比率变化 | **百分点 `p.p.`**，保留 1 位小数 |
| 比率分母为 0 | `—` |
| 比率有分母但分子为 0 | `0.0%` |
| 计算精度 | 使用原始分子、分母计算；仅最终展示时四舍五入 |

### 4.5 会话数卡片细分

会话数卡片的主要信息层级：

1. 卡片标题「会话数」。
2. 当前会话数 N 及相对上一周期的变化标签。
3. 第三行辅助文案 **`对比上期 + 上期会话数`**，例如 `对比上期 900`。
4. 在同一张卡片内部额外展示 **「有效会话：V」**和**「无效会话：I」**。

- **不额外新增两张指标卡片，也不展示「待判定」。**
- 有效/无效仅展示对应数量，未确认新增各自的独立环比或趋势曲线，本期不做。
- 当前值和上期数值均不带「场」单位。
- 指标卡片只读，不可点击跳转。

## 5. 核心指标较上期对比

### 5.1 卡片文案与信息层级

统一采用「指标名称 → 当前值 + 涨跌提示 → 对比上期 + 上期数值」三层展示。

| 指标 | 当前值 | 涨跌标签 | 辅助文案 |
|---|---|---|---|
| 会话数 | `200` | `↑ 100.0%` | `对比上期 100` |
| AI 解决率 | `70.0%` | `↑ 10.0 p.p.` | `对比上期 60.0%` |
| 转人工率 | `18.2%` | `↓ 3.8 p.p.` | `对比上期 22.0%` |

- `p.p.` 为 *percentage points*（百分点），比率从 60% 到 70% 为**上升 10.0 p.p.**，不能写成「上升 10.0%」。
- 会话数变化为相对增长率 `(本期N－上期N)/上期N×100%`，两个比率比较**百分数本身的差**。
- 正变化显示 `↑`，负变化显示 `↓`，完全相等显示 `0.0%` 或 `0.0 p.p.` 而不显示箭头。
- 会话数增减是中性数量变化，不直接判定好坏；解决率上涨、转人工率下降通常是积极变化。不得只依赖颜色传达正负，必须有箭头和数字。
- 保持原简体中文 / English 国际化机制；英文对应的对比说明可按相同语义本地化。

### 5.2 上一周期的选择

| 当前时间筛选 | 当前周期 | 上一期 |
|---|---|---|
| 今天 | 今天 00:00 至当前时刻 | 昨天 00:00 至昨天**相同本地时分** |
| 近 7 天 | 今天及前 6 个自然日 | 此前紧邻的连续 7 个自然日 |
| 近 30 天 | 今天及前 29 个自然日 | 此前紧邻的连续 30 个自然日 |
| 自定义日期 | 所选起止日期（含两端） | 紧邻开始日期之前、自然日数量相同的一段日期 |

1. **本期包含今天时**：当前周期统计至当前时刻；上一周期最后一天也按与当前时刻**相同的时分**截断，以避免不等时长比较。其他完整日期正常统计全天。
2. 自定义日期若完全在历史日期，本期及上一期都统计完整自然日。
3. 两期均以**浏览器时区**作为日期边界，均按**会话创建时间**归属；其他 Agent、渠道筛选条件相同。
4. 示例：在 11 月 12 日 13:35 选择近 7 天，本期 11 月 6 日 00:00 至 11 月 12 日 13:35；上一期 10 月 30 日 00:00 至 11 月 5 日 13:35（用户浏览器本地时间）。

### 5.3 对比公式

| 指标 | 计算方式 | 输出 |
|---|---|---|
| 会话数 | `(本期 N－上期 N) ÷ 上期 N × 100%` | `%` |
| AI 解决率 | `本期(S/V×100%)－上期(S/V×100%)` | `p.p.` |
| 转人工率 | `本期(H/V×100%)－上期(H/V×100%)` | `p.p.` |

**当前周期、上一周期的全部 N、V、I、S、H、U 均使用第 3、4 章的新判定口径**，不得沿用旧版本的「全部会话分母」或「全部已结束会话分母」。

### 5.4 对比边界和异常

| 情况 | 展示 |
|---|---|
| 会话数：上期 N=0，本期 N>0 | 涨跌标签显示 `新增`；不将 0→正数解释为增长 100% |
| 会话数：本期 N=0、上期 N=0 | 涨跌标签显示 `—` |
| 会话数：上期 N>0，本期 N=0 | `↓ 100.0%` |
| AI 解决率：本期或上期 V=0 | 较上期变化显示 `—`；主值仍按本期是否可计算展示 |
| 转人工率：本期或上期 V=0 | 较上期变化显示 `—`；主值仍按本期是否可计算展示 |
| 上一期数值可以计算、本期或上期结果相等 | 对比变化显示 `0.0 p.p.`（比率）或 `0.0%`（会话数） |
| 本期或上期加载失败 | 不将失败解释为 0；保留已成功获取的原数据并提示失败 |
| 会话后来关闭或结果判定更新 | 刷新时本期与上一期均按最新判定回算至各自创建日期 |

## 6. 全局筛选

### 6.1 筛选字段

| 筛选项 | 类型 | 默认值 | 选项 / 展示 |
|---|---|---|---|
| 日期 | 快捷时间范围 + 自定义起止日期 | **近 7 天** | 今天、近 7 天、近 30 天、自定义日期 |
| AI Agent | 单选下拉 | **全部 AI Agent** | 全部 AI Agent + 当前存在的 AI Agent 名称 |
| 渠道 | 单选下拉 | **全部渠道** | 全部渠道 + 具体渠道实例，采用「渠道类型图标 + 渠道名称」 |
| 刷新 | 按钮 | — | 以当前全部筛选条件刷新总览数据 |

### 6.2 日期筛选规则

1. 「今天」从用户浏览器本地当日 00:00 至当前时刻。
2. 「近 7 天」包括今天及之前 6 个自然日；「近 30 天」包括今天及之前 29 个自然日。
3. 自定义日期范围包含开始日期、结束日期当天；结束日期不得早于开始日期；不允许选择未来日期。
4. 自定义范围如果包含今天，今天只统计至当前时刻。
5. 日期边界、趋势图按天/周/月分桶、上一周期范围全部采用**当前用户浏览器时区**；同一租户成员在不同浏览器时区查看时，按本地日期划分结果可不同。
6. 数据按**会话创建时间**归属，**且必须已结束**才进入本模块的统计集合；并非按会话关闭时间归属。

### 6.3 AI Agent 筛选规则

1. 单选，默认全部 AI Agent。
2. 仅当前存在的 Agent 可被单独选择；已删除的 Agent 不出现在列表。
3. 历史会话按**创建时关联的 Agent**归属，不随渠道后续改绑 Agent 改变。
4. 删除 Agent 后，历史会话仍计入「全部 AI Agent」，不支持单独筛选已删除 Agent。
5. 其他现有 Agent 即使暂未开启接待，也不因为不活跃而自动被排除出选择列表。

### 6.4 渠道筛选规则

1. 单选，默认全部渠道。
2. 筛选**具体渠道实例**，不是只筛选 LiveChat/TG 等渠道类型。
3. 渠道选项使用「渠道类型图标 + 渠道名称」展示。
4. 删除渠道后，其历史会话仍计入「全部渠道」，已删除渠道不支持单独选择。
5. 渠道停用不移除原历史统计数据。

### 6.5 筛选组合及变更

1. 三个条件**独立组合生效**，取当前时间、AI Agent、渠道的交集，同时作用于卡片、有效/无效细分和趋势图。
2. AI Agent 与渠道的选项不随对方选择联动缩减，因此可以查询「旧 Agent + 已改绑渠道」的历史会话。
3. 无匹配会话时保留当前筛选，不自动重置。
4. 如果当前选中的 Agent 或渠道被删除导致选项失效，重置该单项为「全部 AI Agent」或「全部渠道」，其他筛选条件保持不变。
5. 每次筛选变更，刷新当前指标、上期对比及图表；无需手动点击刷新才生效。

## 7. 数据趋势

### 7.1 趋势图结构与控件

1. 只展示**一张趋势折线图**。
2. 指标切换使用**单选下拉菜单**，选项依次为「会话数」「AI 解决率」「转人工率」，默认**会话数**。
3. 一次只绘制一个指标，不叠加三条不同指标曲线，不把会话数量和百分比放在一条纵轴。
4. 选中**「AI 解决率」**且用户有收件箱权限时，在**指标下拉菜单左侧**显示按钮：**「查看已解决会话」**（英文：`View solved chats`）。
5. 选中「会话数」或「转人工率」时不显示该按钮；没有收件箱权限时，即使选中 AI 解决率也不显示该按钮。
6. 图表与页面的日期、Agent、渠道筛选一致；不提供图表自身的另一套筛选项，不增加上期对照曲线。

### 7.2 时间粒度

| 当前时间选择 | 趋势粒度 |
|---|---|
| 今天 | 小时 |
| 近 7 天 | 天 |
| 近 30 天 | 天 |
| 自定义范围 ≤30 个自然日 | 天 |
| 自定义范围 31～90 个自然日 | 周 |
| 自定义范围 >90 个自然日 | 月 |

- 每周从**周一**开始。
- 首尾不足整周、整月的时间桶，仅计入所选筛选范围内的会话。
- 每个桶按会话**创建时间**归属，并且只计入**已结束会话**。
- 每个桶的解决率必须按该桶 `S/V` 重新计算，转人工率按该桶 `H/V` 重新计算；不得直接平均已有的日百分比。

### 7.3 数值与悬停展示

| 当前指标 | 数据值 | 悬停显示 |
|---|---|---|
| 会话数 | 当前时间桶的 N | 时间 + 会话数整数 |
| AI 解决率 | 当前时间桶 `S/V × 100%` | 时间 + AI 解决率（1 位小数） |
| 转人工率 | 当前时间桶 `H/V × 100%` | 时间 + 转人工率（1 位小数） |

- 悬停只展示**时间和当前选中指标值**；不附带分子、分母或另一指标。
- 会话数没有数据时展示数值 `0`。
- `V=0` 的百分比时间桶没有可计算比例，不绘制有效比例点，不让折线连接跨越该无效点；对应时间提示「暂无可计算数据」。
- 当前筛选结果完全没有已结束会话时，趋势图区域展示「暂无数据」。

### 7.4 「查看已解决会话」跨模块跳转

**触发条件：**数据趋势下拉选中「AI 解决率」且用户有「收件箱」菜单权限。

**点击行为：**

1. 跳转至 **AI Agent 工作台 → 收件箱 → 已解决**分组。
2. **清空收件箱此前的搜索关键词及原有筛选条件**，统一应用从总览带来的当前筛选条件。
3. 继承**总览当前日期范围的实际起止时间、AI Agent、具体渠道实例**；总览选择「全部 AI Agent」「全部渠道」时，对应收件箱也使用全部。
4. 日期筛选按**会话创建时间**，且仅展示符合「收件箱 → 已解决」判定的已结束会话；不得改为按关闭时间或解决判定时间筛选。
5. 点击前总览所选范围若无已解决会话，按钮**仍显示且可点击**；跳转后展示收件箱已有的「暂无已解决会话」空状态。
6. 上一期对比只用于总览卡片，**不传递上一期**到收件箱。
7. 通过**浏览器返回**回到总览时，保留此前日期、Agent、渠道筛选条件，以及趋势图下拉菜单的指标选择（仍选 AI 解决率时继续展示按钮）。
8. 不改变收件箱原有会话列表排序、消息详情、搜索能力、权限或其他分组功能；「已解决」分组沿用收件箱现有判定，不因会话触发过转人工而排除。

**跨模块日期一致性补充：**原《AI Agent项目 V1.0需求文档》仅写明「已解决」支持日期筛选，未明确日期归属字段。本次规定，从总览跳转后及收件箱「已解决」的日期筛选，**统一按照会话创建时间**。例如 11 月 10 日创建、11 月 12 日解决并结束的会话，筛选 11 月 10 日应可在总览分子及跳转后的已解决列表中同时找到。

**统计关系：**当时间、Agent、渠道范围相同且用户具备权限时，跳转后符合条件的已解决会话数量应对应总览 AI 解决率的**分子 S**；不能拿总览的百分比数值与会话条数直接比较。

## 8. 加载、刷新、空状态和异常处理

### 8.1 刷新机制

1. 首次进入总览，加载当前筛选条件下的全部卡片数据、有效/无效数量、较上期对比和趋势图。
2. 修改任意全局筛选条件，自动重新获取上述数据。
3. 点击「刷新」重新获取当前筛选条件的数据。
4. 本期**不定时自动刷新、不实时推送**。
5. 刷新不清空用户选择的日期、Agent、渠道及趋势指标；刷新失败应保留先前成功加载的数据并提示重试。

### 8.2 页面状态

| 场景 | 处理规则 |
|---|---|
| 首次加载 | 卡片和趋势图保留布局，展示加载状态 |
| 没有任何符合条件的已结束会话：N=0 | 会话数、有效会话、无效会话均为 `0`；解决率和转人工率为 `—`；趋势图「暂无数据」 |
| 有已结束会话，但全部无效：N>0、V=0 | 会话数与无效数正常展示，有效数为 `0`；两项比率 `—`；对应趋势百分比无可计算数据 |
| 已结束有效会话存在，但全部未解决且未转人工 | `S=H=0`，两项比率均为 `0.0%` |
| 没有已解决会话，且趋势选中 AI 解决率 | 有收件箱权限时仍可点击「查看已解决会话」，目标展示收件箱既有空状态 |
| 加载失败、手动刷新失败 | 保留当前筛选及此前成功数据，显示失败提示并允许重试；不当作 `0` 统计 |
| 当前 Agent/渠道已删除 | 对应筛选重置为全部，历史已结束会话仍纳入全部汇总 |
| 无总览权限 | 不展示菜单，直接 URL 访问按现有权限处理 |
| 无收件箱权限 | 总览可正常查看，但不显示「查看已解决会话」按钮 |

### 8.3 历史会话和统计变化

| 场景 | 规则 |
|---|---|
| 会话创建于某日、之后才关闭 | 关闭后才进入总览统计，且归属**原创建日期**；过去日期的 N/V/I/S/H/U 可变化 |
| AI Agent 后续删除 | 历史会话保留，全部 Agent 汇总包含相关历史；不可选择已删除 Agent |
| 渠道删除 | 历史会话保留，全部渠道汇总包含相关历史；不可选择已删除渠道 |
| 渠道改绑 AI Agent | 历史会话仍按创建时的 Agent 归属 |
| 已结束会话结果重新判定 | 重新加载时按最终结果更新，仍需满足已解决与转人工互斥 |
| 浏览器时区不同 | 按各自本地日界线、时间分桶进行统计和跳转日期传递 |

## 9. 与 AI Agent 原 PRD 的同步补充

本章对应原《AI Agent项目 V1.0需求文档》的**「3.1.2 核心名词定义」「3.1.3.3 已解决」「3.1.7 筛选」**，以避免总览与收件箱口径不一致。

### 9.1 「已解决」定义补充

**已解决：**会话已结束，由 AI Agent 至少解决一个真实业务问题。

**判定说明：**

- 会话是否触发过转人工，不作为「已解决」的排除条件；LiveChat 已实际执行转人工指令，或 TG 已成功发送转人工链接的会话，只要满足上述条件，仍可归入「已解决」。
- 即使 AI 先解决一个实际业务问题，之后客户又提出另一问题并触发转人工，收件箱仍可将该会话归入「已解决」；总览的「AI 已解决」按 3.4 节的互斥规则单独判定。
- 「已解决」仍属于「已结束」的子集；不改变收件箱原有分组和会话关闭机制。
- 「已解决」仍沿用原有 LLM 对真实业务问题是否至少解决一个的判断方式；本次不新增转人工排除条件。

### 9.2 收件箱已解决日期筛选补充

- 「收件箱 → 已解决」支持按**会话创建时间**筛选，与总览一致。
- 总览跳转时，自动应用传递的实际起止时间、Agent、渠道条件；原收件箱搜索关键词和筛选条件清空。
- 未从总览进入时，已解决分组既有日期筛选也使用创建时间口径。
- 不新增日期字段切换器，不改变其他收件箱分组。

### 9.3 修改边界

本次对原 AI Agent PRD 的修订是**「已解决」会话级别的排除条件及「已解决」日期筛选依据的补充**，不是重新定义有效业务问题、重新设计收件箱状态、改变超时关闭规则，或给收件箱增加新的会话结果分组。

## 12. V1.0 需求边界总结

1. **仅统计已结束的正式会话**；有效 + 无效 = 已结束会话总数，不新增待判定。
2. 有效性由**是否存在真实业务咨询**决定，不因 AI 未解决或客户未回复直接判无效。
3. 有效会话最终结果为**转人工、已解决、未解决**三者之一，转人工优先，互斥计数。
4. **AI 解决率 = AI 独立解决的已结束有效会话数 ÷ 全部已结束有效会话数**。
5. **转人工率 = 触发转人工的已结束有效会话数 ÷ 全部已结束有效会话数**。
6. LiveChat 以实际执行转人工指令为准；TG 以**成功发送转人工链接**为准；不追踪点击、不按 N 分钟推定。
7. 三张核心卡片不变；会话数卡片内新增有效/无效细分；较上期文案统一为「对比上期 + 数值」，会话数不加「场」，比率变化用 `p.p.`。
8. 趋势指标切换改为**下拉单选**；选中 AI 解决率时在**下拉左侧**显示「查看已解决会话」（需收件箱权限）。
9. 点击按钮进入收件箱「已解决」，**清空原有搜索/筛选、继承当前日期/Agent/渠道**，日期统一按会话创建时间；浏览器返回恢复总览状态。
10. 保留原会话状态、关闭流程、菜单级权限体系；**AI Agent 原 PRD 只补充「已解决」的转人工排除及对应日期筛选规则**。

**文档结束。**
